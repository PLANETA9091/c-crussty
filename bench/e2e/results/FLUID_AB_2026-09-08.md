## 4. Engineering lessons landed in code/docs (each cost a run or a crash)

1. **forceload takes BLOCK coordinates** — the chunk-coord form marked 1
   chunk ~500 blocks from spawn; items summoned into non-ticking spawn
   chunks VANISHED (<5 s), silently invalidating runs 1/99 (symptom:
   summoned=0/400 grep + "No entity was found" kills). Fixed to
   -576 -368 -529 -321; items verified alive at T+2/10/30 s.
2. **Exact-bits box keys never hit for ground items** (S7-25 pilot):
   friction drift rebuilds the AABB with new double bits every tick —
   0% hit rate. Guard key = quantized deflated CELL bounds (sound: the
   negative outcome is cell-set-determined). This redesign is what produced
   the 96.4% hit rate.
3. **define_class racing the POST-Done class-load storm crashes the JVM**
   (hs_err_pid3158, SIGSEGV inside defineClass1 on the Server thread at
   Done+4 s): the arming chain now settles +20 s after the boot marker,
   replicating the empirically-stable perlin window (Done+15-80 s).
4. **JNI FindClass from a native attachment cannot see classes defined into
   the kernel loader's runtime package** — the self-test resolves the bridge
   via a stored GLOBAL jclass (the first fix attempt stored a dangling local
   ref; caught and corrected with new_global_ref before delete_local_ref).
5. **Deploy race = SIGILL**: overwriting libcrussty.so while another agent's
   JVM was starting mapped a half-written agent (hs_err_pid4481). Deploys
   must hold the lane.
6. **Two-agent lane interleaving produced a Frankenstein run** (armed
   markers from a port-bind-crashed JVM + measurement on the other agent's
   dormant server + "Killed 800" double load): documented in CLAIMS, run
   quarantined under invalid_interleave_12xx/, series restarted clean.
