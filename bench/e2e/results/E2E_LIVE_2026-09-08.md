## P0 FINDING — armed improved_noise crashes the JVM on live server

- Config: master .so (5e396db2, rev 839aefc), `CRUSSTY_NATIVE_IMPROVED_NOISE=1`.
- Timeline: boot Done (18.161s) → improved_noise/area_map force-load kicks
  (`forcing kernel load ... (attempt 1..4)`, `Class.forName ... succeeded` ×3) →
  **SIGSEGV (0xb) at pc=0x0000000000000000** in `hs_err_pid18761.log`.
- Crash thread: **"Server thread"** `_thread_in_native` — a native call on the main
  server thread, NOT the plugin poller. Null function pointer (pc=0x0).
- hs_err is degenerate: HotSpot's own error reporter SIGBUSed twice while printing
  the problematic frame and native stack (no stack, no library attribution).
- Timing correlates with the armed improved_noise activation window: the first
  terrain/noise work on the Server thread happens right after spawn-area prep,
  i.e. exactly when retransformed `ImprovedNoise.noise` would first enter the
  native kernel. Init-time `live proof: normalNoise.nativeCheck() = 1` PASSED
  earlier, so the crash is call-path-dependent, not load-dependent.
- Working hypothesis (to verify): a NULL entry in the JNI native-call path after
  retransform-on-live-class — race between the poller's force-load/retransform
  kicks (attempts 2-4 all succeeded) and the first Server-thread noise call, or a
  missing kernel-selection binding leaving a null fn-pointer in the woven
  dispatch. kernel_pref binding line was present (`newCombinedUpdateSummary →
  oldFourUpdateSummary`), so the policy registry itself initialized.
- NOT yet isolated: old deployed .so (d92ed5a0) + armed env (regression window vs
  always-broken). NEXT session should A/B that (boot armed with .bak-f86c517-era
  build, 60s watch, no console input needed — kicks fire automatically).
