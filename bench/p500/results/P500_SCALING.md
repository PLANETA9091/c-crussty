# P500 scaling study — regression groups (2026-09-07)

Question: are the reported regressions real, or artifacts of the synthetic
batch size N (first int argument)? Method: re-run each suspicious group at
N = 16 / 256 / 4096 in fresh JVMs. A bench artifact would change the RATIO
with N; a genuine regression keeps it.

## Verdict: all four are GENUINE, scale-invariant regressions

| pair (class) | N=16 | N=256 | N=4096 | verdict |
|---|---:|---:|---:|---|
| LevelChunkHeightmap: newCombinedUpdateSummary / oldFourUpdateSummary | 0.20x | 0.18x | 0.18x | genuine ~5.5x regression |
| MarkerCache: cachedSummary / oldSummary | 0.23x | 0.22x | 0.22x | genuine ~4.6x regression |
| PalettedReencodeScratch: directPackedSummary / oldNewArraySummary | 0.44x | 0.44x | 0.42x | genuine ~2.3x regression |
| ProtoChunkHeightmap: newCachedContainsSummary / oldEnumSetForeachSummary | 0.67x | 0.59x | 0.56x | genuine ~1.7x regression |

All kernels are O(N) in the first int (linear to slightly superlinear), so
the ratios are stable — the optimized variants do consistently more work per
element than the old paths for these four groups.

## WaypointHotPath — the "0.01x regression" was a pairing artifact

WaypointHotPath `(I)D` kernels are O(N) in the int (waypoint count):

| method | N=1 | N=16 | N=256 | N=4096 |
|---|---:|---:|---:|---:|
| oldReallyFarValue | 22.8 ns | 81.0 ns | 1.0 µs | 15.0 µs |
| guardedReallyFarValue | 19.9 ns | 66.3 ns | 1.0 µs | 16.3 µs |
| oldAzimuthValue | 31.2 ns | 161.3 ns | 2.2 µs | 37.3 µs |
| directAzimuthValue | 23.0 ns | 138.9 ns | 2.2 µs | 36.8 µs |
| oldWaypointManagerValue | 232.6 ns | 6.4 µs | 99.8 µs | 1.71 ms |
| optimizedWaypointManagerValue | 212.1 ns | 6.0 µs | 93.0 µs | 1.60 ms |

Same-stem pairs are parity to modest wins (optimizedWaypointManagerValue is
1.07–1.10x FASTER than oldWaypointManagerValue). The first report compared
optimizedWaypointManagerValue against oldReallyFarValue — kernels that do
different work — and reported a bogus 0.01x. The aggregator now pairs by
longest common suffix of the kernel name (P500 stem rule).
