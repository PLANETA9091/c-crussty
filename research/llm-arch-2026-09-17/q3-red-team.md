### **(1) ENT-BP wiring: entity_mirror.rs**
**Механизм:** Замена `ChunkEntitySlices$EntityCollectionBySection.getEntities` на нативный `entity_mirror.rs` (16³ grid + SoA + AVX2, 0 allocs fast path).  
**Целевой узел:** 3.79% presence, из которого:
- Loop self: 0.68%
- `AABB.intersects`: 1.13%
- `getBoundingBox`: 0.14%
- `fastutil map`: 0.32%  
**Итого оптимизируемое ядро:** **~2.27% absolute**.

**Атака на механизм:**
- **Parity:** `predicate retention` (1.3%) — критичен. `Scoreboard.getPlayersTeam` в Java-коде может нарушиться, если нативная версия не повторит логику фильтрации.  
- **JNI-overhead:** ~40–60 нс/вызов (при 10K+ вызовов/тик → 0.4–0.6% MSPT).  
- **Потолок эффекта:**  
  - Теоретический максимум: 2.27% MSPT.  
  - Реалистичный: 1.5–1.8% (с учётом predicate retention и JNI).  
- **Гейт:** **Не проходит** (1.8% < 3%).

**Вердикт:** **NO-GO**. Потолок эффекта ниже порога, даже при идеальной реализации.

### **(2) PALETTE zero-copy lens**
**Механизм:** Zero-copy доступ к `PalettedContainer.get` через JNI-ленс.  
**Целевой узел:** 3.7% presence (лист в горячем пути).

**Атака на механизм:**
- **Parity:** `PalettedContainer` — это палитра ID + данные. Нативный ленс должен гарантировать бит-точное чтение (включая версионность).  
- **JNI-overhead:** ~30 нс/вызов (при 50K+ вызовов/тик → 1.5% MSPT).  
- **Потолок эффекта:**  
  - Оптимизация доступа к данным: 20–30% от 3.7% → 0.7–1.1% MSPT.  
  - Итого: 0.7–1.1% (вычитаем JNI-overhead → **0% чистый выигрыш**).  
- **Гейт:** **Не проходит** (чистый выигрыш ≤0%).

**Вердикт:** **NO-GO**. JNI-overhead съедает весь потенциальный выигрыш.

### **(3) BOAT whole-body hot-patch**
**Механизм:** Замена `AbstractBoat.tick` на нативную реализацию (физика + коллизии + пассажиры).  
**Целевой узел:** 9.66% presence.

**Атака на механизм:**
- **Parity:**  
  - Физика: позиция/скорость — можно бит-точно.  
  - Клиент-side предсказание: `lerp` для клиентов — требует синхронизации с Java-кодом.  
  - Пассажиры: `Entity.passenger` — сложно в нативе.  
- **JNI-overhead:** ~50 нс/вызов (при 1K+ вызовов/тик → 0.05% MSPT).  
- **Потолок эффекта:**  
  - Оптимизация цикла: 50–70% от 9.66% → 4.8–6.7% MSPT.  
  - Итого: **4.5–6.2%** (после учёта parity-рисков).  
- **Гейт:** **Проходит** (6.2% > 3%).

**Вердикт:** **GO**, но с рисками parity для пассажиров и client-side lerp.

### **(4) RANDOM-TICK SIMD RNG**
**Механизм:** Векторизация `random-tick` (4.5% кластер) через SIMD RNG с сохранением бит-точности Java `Random`.  
**Целевой узел:** `optimiseRandomTick` (2.2%) + `advanceSeed` (1.7%).

**Атака на механизм:**
- **Parity:** Java `Random` — Linear Congruential Generator (LCG). SIMD-версия должна повторять последовательность бит-точно.  
- **JNI-overhead:** ~20 нс/вызов (при 10K+ вызовов/тик → 0.2% MSPT).  
- **Потолок эффекта:**  
  - Векторизация: 4x throughput → 75% от 4.5% → 3.4% MSPT.  
  - Итого: **3.2%** (после учёта JNI).  
- **Гейт:** **Проходит** (3.2% > 3%).

**Вердикт:** **GO**, но требует тщательного тестирования parity (20000+ тестов).

### **(5) GC allocation-shape**
**Механизм:** Уменьшение аллокаций в entity-запросах через caller-owned буферы + арены.  
**Целевой узел:** GC 9.5% (G1 barriers 4.7% + G1 worker 4.0%).

**Атака на механизм:**
- **Parity:** Не влияет на логику, но требует аккуратного управления буферами.  
- **JNI-overhead:** ~10 нс/вызов (при 5K+ вызовов/тик → 0.05% MSPT).  
- **Потолок эффекта:**  
  - Снижение аллокаций: 30–50% от 9.5% → 2.85–4.75% MSPT.  
  - Итого: **2.8–4.7%** (после учёта JNI).  
- **Гейт:** **Условно проходит** (4.7% > 3%, но нижняя граница ниже).

**Вердикт:** **GO**, но требует точного профилирования allocation hotspots.

### **Победитель следующего раунда: (3) BOAT whole-body hot-patch**
**Механизм:**  
- **Hook:** `AbstractBoat.tick` (метод в `net.minecraft.world.entity.vehicle.Boat`).  
- **Реализация:** Нативный `boat_native.rs` с:  
  - Физика (позиция/скорость/коллизии) — бит-точная.  
  - Пассажиры — делегация обратно в Java (через JNI-кalls).  
  - Client-side lerp — синхронизация с Java через timestamp.  

**Метрика и порог гейта:**  
- **Метрика:** MSPT reduction в `boat`-подсистеме.  
- **Порог:** **≥5%** (чтобы покрыть риски parity).  

**Parity-протокол:**  
- **Тесты:** 10K+ тиков лодок в разных условиях (вода/лава/сухопутье).  
- **Проверка:** Сравнение позиции/скорости/пассажиров между Java и нативом.  

**Лестница верификации:**  
1. **Unit-тесты:** Нативная физика изолированно.  
2. **Интеграционные тесты:** Лодка в мире (без игроков).  
3. **A/B-тест:** Сравнение MSPT/TPS на реальном мире (MineShield-3).  
4. **Параллельная сборка:** Включение в CI с parity-чеками.  

---

### **3 дополнительные метрики для CI Benchmark 3.0**  
1. **JNI-overhead metric:** Время, проведанное в JNI-коде (в % от MSPT).  
2. **Parity delta:** Разница в состояниях (позиции/скорости) между Java и нативом.  
3. **Allocation rate:** Количество аллокаций/тик (для GC-оптимизаций).  

**Итог:** **BOAT hot-patch** — единственный кандидат, чей потолок эффекта (>5%) гарантированно проходит гейт. Остальные либо не дотягивают до 3%, либо рискованны с parity.
